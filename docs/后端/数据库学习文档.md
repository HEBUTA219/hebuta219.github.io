# 数据库学习文档

# 第一阶段：数据库基础认知

##  一、什么是数据库？

数据库（Database，简称DB）是**按照数据结构来组织、存储和管理数据的仓库**，本质是一个长期存储在计算机内、有组织、可共享、统一管理的大量数据的集合。简单说，就是把分散的数据集中放在一起，方便我们查询、修改、删除和新增的“数据容器”。

对比生活场景：数据库就像家里的衣柜，衣服（数据）按季节、类型（数据结构）分类存放，需要时能快速找到，而不是杂乱堆在箱子里（文件存储）。

## 二、数据库核心概念

- **数据库管理系统（DBMS）**：操作和管理数据库的软件（如MySQL软件），是用户与数据库之间的接口。
- **表（Table）**：数据库的基本存储单位，由行和列组成（类似Excel表格）。例：学生表（学号、姓名、年龄、性别）。
- **行（Row）**：表中的一条具体数据，也称“记录”。例：一行数据对应一个学生的信息。
- **列（Column）**：表中的一个数据类别，也称“字段”，每个列有对应的数据类型（如姓名是字符串类型，年龄是数字类型）。
- **主键（Primary Key，PK）**：表中唯一标识一条记录的字段，不能重复、不能为空。例：学生表的“学号”。
- **外键（Foreign Key，FK）**：用于关联两个表的字段，指向另一个表的主键。例：成绩表的“学号”指向学生表的“学号”，确保成绩数据对应到具体学生。
- **模式（Schema）**：关于数据库和表中的布局以及特性的信息。一般模式会定义数据在表中如何存储，包含存储什么样的数据，数据如何分解，以及各个部分的信息如何命名等信息。类似于数据库中的“文件夹”，主要作用是用于分类，隔离数据库对象（表，试图，索引，存储过程等），来避免命名冲突，同时管理权限。

##  三、数据库的核心作用

- **数据存储**：替代传统的Excel、TXT文件，支持海量数据长期存储，避免数据丢失。

- **数据管理**：统一管理数据，实现数据的增删改查（CRUD），并保证数据的一致性、完整性。

- **数据共享**：多个用户或程序可同时访问同一数据库，比如电商平台的商品数据，商家和消费者都能查看。

- **数据安全**：通过权限控制（如谁能看、谁能改）保护数据，防止非法访问和篡改。

## 四、数据库的分类（重点掌握关系型数据库）

###  1. 关系型数据库（RDBMS）

核心特点：数据以**表格**形式存储，表格之间通过**关系**关联（如学生表和成绩表通过学号关联），支持SQL查询，数据一致性强。

缺点：缺乏灵活性，需求迭代快速的开发环境中，每次修改表结构都是一项复杂且耗时的任务，尤其是在处理海量数据时。

常见产品：

- MySQL：开源免费，轻量易用，适合中小型项目、学习场景，市场占有率极高。

- Oracle：商业级数据库，功能强大，稳定性好，适合大型企业（收费，入门不推荐）。

- SQL Server：微软产品，适合Windows环境，在.NET项目中常用（部分功能收费）。

- PostgreSQL：开源，功能全面，支持复杂数据类型和自定义函数（进阶后可了解）。

###  2. 非关系型数据库（NoSQL）

核心特点：不依赖表格结构，数据存储格式灵活（如**键值对、文档、图形**），适合海量数据、高并发场景，一致性要求较低。

常见产品：

- Redis：**键值对**数据库，内存存储，读写速度极快，常用于缓存、会话存储。

- MongoDB：**文档型**数据库，存储BSON(Binary JSON:是一种二进制编码的JSON衍生格式)数据，适合内容管理、日志存储。

  **补充知识**：JSON是纯文本格式，仅仅支持有限的基础数据类型，而BSON是二进制编码格式

- Neo4j：**图形**数据库，适合处理人际关系、网络拓扑等关联数据(所有网络都可以被结构化为相互连接的关系图)

## 五、SQL分类（DQL,DML,DDL,DCL）

### 1. 数据查询语言（DQL：Data Query Language）

**核心作用**：从数据库表中提取所需数据，是使用频率最高的SQL类别，**仅查询数据不修改数据，不影响表结构和表中记录**。

**核心关键字**：SELECT（必选），搭配 WHERE、ORDER BY、DISTINCT、LIMIT、JOIN、聚合函数（COUNT/SUM/AVG等）、子查询等使用。

**文档对应案例**：

```sql
-- 基础查询
SELECT name, age, gender FROM student;

-- 条件查询
SELECT * FROM student WHERE gender = '女'; -- 等值条件
SELECT * FROM student WHERE age BETWEEN 18 AND 20; -- 范围条件
SELECT * FROM student WHERE gender = '男' AND age = 18; -- 逻辑条件
-- 排序、分页查询
SELECT * FROM student ORDER BY age ASC LIMIT 1, 3;
-- 多表关联查询
SELECT s.name, sc.subject, sc.score FROM student s INNER JOIN score sc ON s.id = sc.student_id;
```

**特点**：执行后**仅返回结果集**，无副作用（**不会修改数据**、**不会创建/删除表**）。

### 2. 数据操纵语言（DML：Data Manipulation Language）

**核心作用**：对表中的数据进行新增、修改、删除操作（即CRUD中的CUD），仅**操作数据，不改变表结构**。

**核心关键字**：INSERT（新增/创建）、UPDATE（修改/更新）、DELETE（删除）。

```sql
-- 新增数据
INSERT INTO student (name, age, gender) VALUES ('张三', 18, '男');
-- 修改数据
UPDATE student SET age = 21 WHERE name = '张三';
-- 删除数据
DELETE FROM student WHERE id = 4;
```

**特点**：操作会改变表中数据，需谨慎使用（尤其是UPDATE和DELETE，需加WHERE条件避免误操作全表）；支持事务回滚（执行后未提交可恢复数据）。

**为什么DML支持事务回滚？**

数据库执行 DML 操作时，不会立刻修改磁盘上的原始数据，而是先在**内存 / 日志**中记录操作的 “反向操作”（比如 INSERT 的反向是 DELETE，UPDATE 的反向是恢复原值），事务回滚时，数据库会执行这些反向操作，将数据恢复到事务开始前的状态。

### 3. 数据定义语言（DDL：Data Definition Language）

**核心作用**：定义数据库和表的结构，包括创建、修改、删除数据库、表、索引、约束等，**操作对象是“结构”而非数据**。

**核心关键字**：CREATE（创建）、ALTER（修改）、DROP（删除）、TRUNCATE（清空表结构并重置）。

```sql
-- 创建数据库，并指定字符集为utf8mb4
CREATE DATABASE school CHARACTER SET utf8mb4;
-- 创建表,id字段为主键且递增，name字段非空
CREATE TABLE student (id INT PRIMARY KEY AUTO_INCREMENT, name VARCHAR(20) NOT NULL);
-- 修改表结构，新增phone字段并且设置为唯一约束
ALTER TABLE student ADD phone VARCHAR(11) UNIQUE;
-- 删除表
DROP TABLE stu;
-- 清空表数据并重置结构
TRUNCATE TABLE student;
```

**特点**：操作会改变数据库/表结构，执行后立即生效，多数操作不可逆（如DROP TABLE删除表后无法恢复）；TRUNCATE与DELETE的区别：TRUNCATE是DDL（重置结构，不可回滚），DELETE是DML（逐行删除，可回滚）。

### 4. 数据控制语言（DCL：Data Control Language）

**核心作用**：**管理数据库权限和事务**，确保数据安全和操作一致性，面向数据库用户和事务管理。

**核心关键字**：GRANT（授予权限）、REVOKE（撤销权限）、COMMIT（提交事务）、ROLLBACK（回滚事务）、START TRANSACTION（开启事务）。

```sql
--创建一个test数据库用户 @localhost为访问来源表示只能在数据库服务器本机登录，若要远程登录改为'test'@'%'，IDENTIFIFD BY设置该用户的登录密码
CREATE USER 'test'@'localhost' IDENTIFIED BY '123456';
--给test用户授予school数据库下所有表（*）的SELECT（查询）和INSERT（插入）权限
GRANT SELECT, INSERT ON school.* TO 'test'@'localhost';
--撤销
REVOKE INSERT ON school.* FROM 'test'@'localhost';

-- 事务管理（由于单个业务操作可能包含多个数据库操作，如果没有全部成功或全部失败，就可能产生脏数据）
START TRANSACTION;
UPDATE user SET money = money - 20 WHERE name = 'A';
UPDATE user SET money = money + 20 WHERE name = 'B';
COMMIT; -- 提交事务
-- ROLLBACK; -- 执行失败时回滚
```

**特点**：主要用于生产环境，小白入门阶段重点掌握事务基础操作，权限管理可后续进阶学习；事务操作需遵循ACID特性（原子性、一致性、隔离性、持久性）。

## 六、数据库表中字段的常见约束类型

- **非空约束（NOT NULL）**：字段值不能为NULL，强制字段必须有值，例如学生姓名，学生学号不能非空

  ```sql
  -- 创建表时指定非空约束
  CREATE TABLE student (
    id INT,
    name VARCHAR(50) NOT NULL,  -- 姓名不能为空
    number VARCHAR(11) NOT NULL  -- 手机号不能为空
  );
  -- 插入数据：name为空会报错
  INSERT INTO student (id, name, number) VALUES (1, NULL, '202522802025');
  -- 错误提示：Column 'name' cannot be null
  ```

- **唯一约束（UNIQUE）**:保证字段值在表中唯一，不重复（允许多个NULL,因为NULL不等于任何值）

  ```sql
  CREATE TABLE student (
    id INT,
    phone VARCHAR(11) UNIQUE  -- 手机号唯一
  );
  -- 插入重复手机号会报错
  INSERT INTO student (id, phone) VALUES (1, '13800138000');
  INSERT INTO student (id, phone) VALUES (2, '13800138000');
  -- 错误提示：Duplicate entry '13800138000' for key 'phone'
  ```

- **主键约束（PRIMARY KEY）**：NOT NULL + UNIQUE的组合，是表中记录的唯一标识且非空（一张表只能有 1 个主键，通常用 id 字段）。

  ```sql
  CREATE TABLE student (
    id INT PRIMARY KEY,  -- 主键：非空+唯一
    name VARCHAR(50)
  );
  -- 主键为空或重复都会报错
  INSERT INTO student (id, name) VALUES (NULL, '张三');  -- 非空报错
  INSERT INTO student (id, name) VALUES (1, '李四');
  INSERT INTO student (id, name) VALUES (1, '王五');     -- 重复报错
  ```

- **自增约束（AUTO_INCREMENT）**:（MySQL 专属）配合主键使用，主键值自动递增，无需手动赋值（简化插入操作）。

  ```sql
  CREATE TABLE student (
    id INT PRIMARY KEY AUTO_INCREMENT,  -- 主键自增
    name VARCHAR(50)
  );
  -- 插入数据时无需指定id，自动生成1、2、3...
  INSERT INTO student (name) VALUES ('张三');  -- id=1
  INSERT INTO student (name) VALUES ('李四');  -- id=2
  ```

- **默认值约束（DEFAULT）**：插入数据时若未指定该字段值，自动填充默认值（比如性别默认 “未知”、状态默认 “正常”）

  ```sql
  CREATE TABLE student (
    id INT,
    name VARCHAR(50),
    gender VARCHAR(2) DEFAULT '未知'  -- 性别默认值
  );
  -- 插入时不指定gender，自动填充“未知”
  INSERT INTO student (id, name) VALUES (1, '张三');
  -- 查询结果：gender字段值为“未知”
  ```

- 外键约束（FOREIGN KEY）：关联两张表（比如学生表关联班级表），保证学生的班级 ID 必须是班级表中存在的 ID，避免无效数据。

  ```sql
  -- 先创建主表（班级表）
  CREATE TABLE class (
    class_id INT PRIMARY KEY,
    class_name VARCHAR(50)
  );
  -- 创建从表（学生表），添加外键关联班级表
  CREATE TABLE student (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    class_id INT,
    -- 外键约束：student.class_id 必须来自 class.class_id
    FOREIGN KEY (class_id) REFERENCES class (class_id)
  );
  -- 插入不存在的class_id会报错
  INSERT INTO student (id, name, class_id) VALUES (1, '张三', 999);
  -- 错误提示：Cannot add or update a child row: a foreign key constraint fails
  ```

# 第二阶段：SQL基础操作

SQL（结构化查询语言）是操作关系型数据库的标准语言，本阶段按功能分类拆解核心操作

## 一、数据库操作（库级）

###  1. 创建数据库

```sql
-- 创建名为school的数据库，指定字符集为utf8mb4（支持中文，避免乱码），
CREATE DATABASE school CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
--COLLATE utf8mb4_general_ci，对字段进行排序或比较时，使用通用算法（Unicode编码值）且ci忽略大小写差异
```

避坑点：字符集必须选utf8mb4（而非utf8），utf8仅支持部分中文，会导致插入中文报错。

###  2. 查看所有数据库

```sql
SHOW DATABASES;
```

###  3. 使用数据库

```sql
-- 操作表前必须先指定数据库
USE school;
```

###  4. 删除数据库

```sql
-- 删除school数据库，所有表和数据会一并删除
DROP DATABASE school;
```

## 二、表操作语句（CREATE TABLE, ALTER TABLE, DROP TABLE）

用于对数据库中的表进行创建、修改、删除，属于表结构层面的操作，需明确字段类型、约束等信息，确保数据规范性。

###  1. 创建表（CREATE TABLE）

创建表需指定表名、字段名、数据类型及字段约束（主键、非空、默认值等），是数据存储的基础。

```sql
-- 创建学生表（student）
CREATE TABLE student (
    id INT PRIMARY KEY AUTO_INCREMENT, -- 学号：主键（唯一标识），自增
    name VARCHAR(20) NOT NULL COMMENT '学生姓名',
    age INT DEFAULT 0 COMMENT '学生年龄，默认0', -- 年龄：默认值0
    gender VARCHAR(2) CHECK (gender IN ('男', '女')) COMMENT '性别，仅允许男/女', -- 检查约束
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间，默认当前时间'
) COMMENT '学生信息表'; -- 给表添加注释
```

关键补充：

- **常用数据类型**：INT（整数）、VARCHAR(n)（可变长度字符串）、DATETIME（日期时间）、DECIMAL(m,n)（高精度小数，适用于金额/分数，其中m表示该小数的总位数/精度，n表示小数位数，例如：DECIMAL(5,2)可存储的数值范围为-999.99~999.99）。
- **常用约束**：PRIMARY KEY（主键）、NOT NULL（非空）、DEFAULT（默认值）、UNIQUE（唯一）、CHECK（检查）。

###  2. 修改表结构（ALTER TABLE）

表创建后，可根据需求新增字段、修改字段、删除字段、修改表名、添加注释等。

```sql
-- 1. 新增字段（添加手机号字段，唯一约束）
ALTER TABLE student ADD phone VARCHAR(11) UNIQUE COMMENT '手机号，唯一';
-- 2. 修改字段数据类型（将手机号长度改为13，适配国际号码）
ALTER TABLE student MODIFY phone VARCHAR(13) COMMENT '手机号（含国际区号）';
-- 3. 修改字段名（将phone改为tel，需重新指定数据类型）
ALTER TABLE student CHANGE phone tel VARCHAR(13) COMMENT '手机号';
-- 4. 删除字段（删除tel字段）
ALTER TABLE student DROP tel;
-- 5. 修改表名（将student改为stu）
ALTER TABLE student RENAME TO stu;
-- 6. 添加主键约束（若创建表时未指定主键）
ALTER TABLE stu ADD PRIMARY KEY (id);
-- 7. MODIFY和CHANGE的区别是MODIFY只能修改字段的属性（类型，长度，约束等），但是不能改字段名，CHANGE既可以修改字段名也可以修改字段属性
```

###  3. 删除表（DROP TABLE）

删除表结构及表中所有数据，操作不可逆，需格外谨慎（学习场景建议先备份）。

```sql
-- 语法：DROP TABLE 表名;
DROP TABLE stu; -- 删除stu表，谨慎使用！
-- 批量删除多个表（用逗号分隔表名）
DROP TABLE IF EXISTS stu, score; -- 加IF EXISTS避免表不存在时报错
```

## 三、数据操作语句（INSERT INTO, UPDATE, DELETE）

用于对表中的数据进行新增、修改、删除，统称CRUD中的CUD操作，其中UPDATE和DELETE需谨慎使用，避免误操作全表数据。

###  1. 新增数据（INSERT INTO）

向表中插入一条或多条数据，支持指定字段插入和全字段插入，推荐指定字段插入（避免表结构变更导致报错）。

```sql
-- 1. 指定字段插入（推荐，忽略自增/默认值字段）
INSERT INTO student (name, age, gender)
VALUES ('张三', 18, '男'); -- id自动递增，create_time取当前时间（默认值）
-- 2. 全字段插入（需按表字段顺序填写，包括自增字段，不推荐）
INSERT INTO student (id, name, age, gender, create_time)
VALUES (2, '李四', 19, '女', '2026-01-21 10:30:00');
-- 3. 批量插入（高效，一次插入多条数据，减少执行次数）
INSERT INTO student (name, age, gender)
VALUES ('王五', 20, '男'), ('赵六', 18, '女'), ('孙七', 19, '男');
```

###  2. 修改数据（UPDATE）

修改**表中已存在的数据**，**必须加WHERE子句指定范围**，否则会修改全表数据（不可逆）。

```sql
-- 1. 修改单条数据
UPDATE student SET age = 21 WHERE name = '张三'; -- 将张三的年龄改为21
-- 2. 批量修改多个字段
UPDATE student SET age = 20, gender = '男' WHERE id = 4; -- 将id=4的学生年龄改为20，性别改为男
```

避坑点：UPDATE语句务必加WHERE子句，无条件修改会导致全表数据异常，且无法直接恢复！

###  3. 删除数据（DELETE）

删除表中的数据，支持按条件删除和全表删除，同样需加WHERE子句，全表删除可选择DELETE或TRUNCATE（二者有差异）。

```sql
-- 1. 按条件删除单条数据
DELETE FROM student WHERE id = 4; -- 删除id为4的学生数据
-- 2. 按条件删除多条数据
DELETE FROM student WHERE age > 20; -- 删除年龄大于20的学生数据
-- 3. 删除全表数据（是DML，可条件删除，支持回滚，,保留表结构，自增字段不重置）
DELETE FROM student;
-- 4. 快速删除全表数据（不可回滚，不保留日志，不可恢复，自增字段重置为1，效率极高）
TRUNCATE TABLE student; -- 等价于删除表后重新创建表，谨慎使用！
```

补充：DELETE是逐行删除（支持回滚），TRUNCATE是重置表结构（不支持回滚），数据量大时TRUNCATE效率更高。

## 四、基础查询语句（SELECT, WHERE, ORDER BY, DISTINCT, LIMIT）

查询是SQL使用频率最高的操作，核心用于从表中提取所需数据，支持条件筛选、排序、去重、分页等功能，以下案例基于`student`表（字段：id、name、age、gender、create_time）。

###  1. 基础查询（SELECT）

用于指定查询字段，支持查询所有字段或特定字段，推荐查询特定字段以提升效率。

```sql
-- 1. 查询所有字段（学习场景可用，生产环境不推荐，效率低）
SELECT * FROM student; -- * 表示匹配表中所有字段
-- 2. 查询指定字段（推荐，仅提取所需数据）
SELECT name, age, gender FROM student;
-- 3. 给字段起别名（AS 可省略，增强结果可读性）
SELECT name AS 学生姓名, age AS 年龄, gender AS 性别 FROM student;
```

###  2. 条件筛选（WHERE）

结合WHERE子句筛选符合条件的数据，支持等值、范围、逻辑、模糊等多种条件。

```sql
-- 1. 等值条件（=）
SELECT * FROM student WHERE gender = '女'; -- 查询性别为女的学生
-- 2. 范围条件（>、<、>=、<=、BETWEEN...AND...）
SELECT * FROM student WHERE age > 18; -- 年龄大于18
SELECT * FROM student WHERE age BETWEEN 18 AND 20; -- 年龄18~20（含边界值）
-- 3. 逻辑条件（AND、OR、NOT取反）
SELECT * FROM student WHERE gender = '男' AND age = 18; -- 男性且年龄18
SELECT * FROM student WHERE age < 18 OR age > 20; -- 年龄小于18或大于20
-- 4. 模糊查询（LIKE）：依赖通配符实现，MySQL支持以下常见通配符
--%：匹配任意长度字符（包括0个字符），可放开头、中间、结尾
SELECT * FROM student WHERE name LIKE '张%'; -- 姓“张”的学生（开头匹配）
SELECT * FROM student WHERE name LIKE '%三%'; -- 名字含“三”的学生（中间匹配）
SELECT * FROM student WHERE name LIKE '%三'; -- 名字以“三”结尾的学生（结尾匹配）
--_：匹配单个任意字符，仅能匹配1个字符，用于固定位置匹配
SELECT * FROM student WHERE name LIKE '_三'; -- 两个字且第二个字是“三”（如李三、王三）
SELECT * FROM student WHERE name LIKE '张__'; -- 三个字且以“张”开头（如张三丰、张小红）
-- 5. 空值判断（IS NULL、IS NOT NULL）
SELECT * FROM student WHERE gender IS NULL; -- 查询性别为空的学生
SELECT * FROM student WHERE gender IS NOT NULL; -- 查询性别非空的学生
```

###  3. 排序（ORDER BY）

按指定字段对查询结果排序，默认升序（ASCENT），可指定降序（DESCENT），支持多字段排序。

```sql
-- 1. 单字段排序
SELECT * FROM student ORDER BY age ASC; -- 按年龄升序（ASC可省略）
SELECT * FROM student ORDER BY age DESC; -- 按年龄降序
-- 2. 多字段排序（先按年龄升序，年龄相同按id降序）
SELECT * FROM student ORDER BY age ASC, id DESC;
```

###  4. 去重（DISTINCT）

去除查询结果中的重复数据，仅保留唯一记录，适用于统计不重复值场景。

```sql
-- 查询所有不重复的年龄
SELECT DISTINCT age FROM student;
-- 注意：DISTINCT 作用于所有查询字段，需所有字段值都相同才会去重
SELECT DISTINCT age, gender FROM student;
```

###  5. 分页（LIMIT）

限制查询结果的条数，适用于分页展示数据，MySQL专属语法（索引从0开始）。

```sql
-- 1. 只查询前3条数据
SELECT * FROM student LIMIT 3;
-- 2. 分页查询（从第2条开始，查询3条数据，即第2、3、4条）
SELECT * FROM student LIMIT 1, 3; --语法：1为LIMIT起始索引, 3为查询条数
```

## 五、子查询与联接（INNER JOIN, LEFT JOIN, RIGHT JOIN, FULL JOIN, SUBQUERY）

实际开发中数据分散在多个表中，需通过联接或子查询关联数据，其中**联接适用于多表关联展示**，**子查询适用于嵌套条件筛选**。

前提：创建成绩表（score），与学生表（student）通过外键关联（student_id对应student.id）。

```sql
CREATE TABLE score (
    id INT PRIMARY KEY AUTO_INCREMENT,
    student_id INT NOT NULL,
    subject VARCHAR(20) NOT NULL,
    score INT NOT NULL,
    FOREIGN KEY (student_id) REFERENCES student(id)
    ON DELETE CASCADE -- 级联删除：学生表数据删除时，成绩表对应数据同步删除
);
-- 插入测试数据
INSERT INTO score (student_id, subject, score)
VALUES (1, '数学', 90), (1, '语文', 85), (2, '数学', 95), (3, '语文', 88);
```

###  1. 表联接（JOIN）

用于关联多个表查询数据，按关联逻辑分为内联接、左联接、右联接、全联接，其中全联接MySQL需通过UNION实现。

```sql
-- 1. 内联接（INNER JOIN）：仅查询两表中匹配的数据（有成绩的学生）
SELECT s.name AS 学生姓名, sc.subject AS 科目, sc.score AS 分数
FROM student s
INNER JOIN score sc ON s.id = sc.student_id; -- ON 指定联接条件

-- 2. 左联接（LEFT JOIN）：保留左表所有数据，右表只匹配关联行，为匹配的列填NULL
SELECT s.name AS 学生姓名, sc.subject AS 科目, sc.score AS 分数
FROM student s
LEFT JOIN score sc ON s.id = sc.student_id;

-- 3. 右联接（RIGHT JOIN）：保留右表所有数据，左表只匹配关联行，为匹配的列填NULL
SELECT s.name AS 学生姓名, sc.subject AS 科目, sc.score AS 分数
FROM student s
RIGHT JOIN score sc ON s.id = sc.student_id;

-- 4. 全联接（FULL JOIN）：查询两表所有数据，MySQL无原生FULL JOIN，用UNION实现
SELECT s.name, sc.subject, sc.score FROM student s LEFT JOIN score sc ON s.id = sc.student_id
UNION
SELECT s.name, sc.subject, sc.score FROM student s RIGHT JOIN score sc ON s.id = sc.student_id;

```

###  2. 子查询（SUBQUERY）

将一个查询结果作为另一个查询的条件、数据源或字段值，分为单行子查询、多行子查询。

```sql
-- 1. 单行子查询（返回一条结果，用=、>、<等符号关联）
-- 查询数学分数大于平均分的学生姓名
SELECT s.name
FROM student s
INNER JOIN score sc ON s.id = sc.student_id
WHERE sc.subject = '数学' AND sc.score > (
    SELECT AVG(score) FROM score WHERE subject = '数学' -- 子查询：获取数学平均分
);

-- 2. 多行子查询（返回多条结果，用IN、ANY、ALL等符号关联）
-- 查询有数学成绩的学生姓名
SELECT name
FROM student
WHERE id IN (
    SELECT student_id FROM score WHERE subject = '数学' -- 子查询：获取有数学成绩的学生id
);

-- 3. 子查询作为数据源（将子查询结果作为临时表）
-- 查询各科平均分及最高分
SELECT subject, avg_score, max_score
FROM (
    SELECT subject, AVG(score) AS avg_score, MAX(score) AS max_score
    FROM score GROUP BY subject -- 子查询：按科目统计平均分和最高分
) AS temp; -- 给临时表起别名temp
```

## 六、函数与聚合操作（COUNT，SUM, AVG, MIN, MAX）

聚合函数用于对数据进行统计计算，需结合GROUP BY分组使用（单独使用时默认对全表聚合），常见函数包括计数、求和、平均值、最大值、最小值。

###  1. 常用聚合函数

```sql
-- 1. COUNT：计数（统计记录条数，忽略NULL值）
SELECT COUNT(id) AS 学生总数 FROM student; -- 按主键计数，效率最高
SELECT COUNT(gender) AS 性别非空数 FROM student; -- 统计性别非空的记录数
-- 2. SUM：求和（仅适用于数值类型字段）
SELECT SUM(score) AS 数学总分 FROM score WHERE subject = '数学'; -- 统计数学科目总分
-- 3. AVG：求平均值（仅适用于数值类型字段，忽略NULL值）
SELECT AVG(score) AS 数学平均分 FROM score WHERE subject = '数学';
-- 4. MAX：求最大值
SELECT MAX(score) AS 数学最高分 FROM score WHERE subject = '数学';
-- 5. MIN：求最小值
SELECT MIN(score) AS 数学最低分 FROM score WHERE subject = '数学';
-- 6. 多函数组合使用
SELECT 
    COUNT(id) AS 学生总数,
    AVG(age) AS 平均年龄,
    MAX(age) AS 最大年龄,
    MIN(age) AS 最小年龄
FROM student;
```

###  2. 分组聚合（GROUP BY）

按指定字段分组，对每组数据单独进行聚合计算，分组后筛选用HAVING（区别于WHERE，WHERE筛选行，HAVING筛选分组）。

```sql
-- 1. 按科目分组，统计每科的平均分、最高分、最低分
SELECT 
    subject AS 科目,
    AVG(score) AS 平均分,
    MAX(score) AS 最高分,
    MIN(score) AS 最低分,
    COUNT(student_id) AS 参考人数
FROM score
GROUP BY subject;

-- 2. 分组后筛选（仅显示平均分大于90的科目）
SELECT subject AS 科目, AVG(score) AS 平均分
FROM score
GROUP BY subject
HAVING 平均分 > 90; -- HAVING 后可直接使用别名

-- 3. 按多字段分组（按科目和性别分组，统计平均分）
SELECT 
    sc.subject AS 科目,
    s.gender AS 性别,
    AVG(sc.score) AS 平均分
FROM score sc
INNER JOIN student s ON sc.student_id = s.id
GROUP BY sc.subject, s.gender;

```

##  七、高级操作（UNION, CASE, INDEX）

包含结果集合并、条件判断、索引管理等高级操作，适用于复杂业务场景，提升SQL灵活性和查询效率。

###  1. 结果集合并（UNION, UNION ALL）

用于合并两个或多个SELECT语句的结果集，要求字段数量、数据类型一致，UNION去重，UNION ALL保留重复值（效率更高）。

```sql
-- 1. UNION（去重合并）：合并数学和语文的成绩，去除重复记录
SELECT student_id, subject, score FROM score WHERE subject = '数学'
UNION
SELECT student_id, subject, score FROM score WHERE subject = '语文';
-- 2. UNION ALL（保留重复合并）：合并结果保留重复记录，效率高于UNION
SELECT student_id, subject, score FROM score WHERE subject = '数学'
UNION ALL
SELECT student_id, subject, score FROM score WHERE subject = '语文';
```

注意：合并的SELECT语句字段顺序、数量、数据类型必须一致，否则会报错。

###  2. 条件判断（CASE）

类似程序中的if-else语句，用于在SQL中实现条件逻辑，返回不同结果，适用于数据分类、值替换等场景。

```sql
-- 1. 简单CASE语句（按值匹配）
-- 给成绩分级：90分及以上为优秀，80-89为良好，60-79为及格，低于60为不及格
SELECT 
    s.name AS 学生姓名,
    sc.subject AS 科目,
    sc.score AS 分数,
    CASE 
        WHEN sc.score >= 90 THEN '优秀'
        WHEN sc.score BETWEEN 80 AND 89 THEN '良好'
        WHEN sc.score BETWEEN 60 AND 79 THEN '及格'
        ELSE '不及格'
    END AS 成绩等级
FROM student s
INNER JOIN score sc ON s.id = sc.student_id;
-- 2. 替换字段值（将性别'男'替换为'男性'，'女'替换为'女性'）
SELECT 
    name AS 学生姓名,
    CASE gender 
        WHEN '男' THEN '男性'
        WHEN '女' THEN '女性'
        ELSE '未知'
    END AS 性别
FROM student;
```

###  3. 索引管理（INDEX）

索引是数据库的“目录”，能大幅提升查询效率，但会降低插入/修改/删除速度（需维护索引），适用于查询频繁、数据量大的表。

如果无索引的话，全表扫描所有行，并筛选符合条件的数据（顺序查找）

有索引的话，直接定位到具体的位置（因为数据库会为索引字段构建有序B+树的数据结构），扫描行数大幅减少，因此查询速度大幅度提高

```sql
-- 1. 创建普通索引（适用于频繁查询的字段，如学生姓名）
CREATE INDEX idx_student_name ON student(name);
-- 2. 创建唯一索引（适用于不允许重复的字段，如手机号，兼具唯一约束和索引功能）
CREATE UNIQUE INDEX idx_student_phone ON student(phone);
-- 3. 创建联合索引（适用于多字段联合查询，如科目+分数）
CREATE INDEX idx_score_subject_score ON score(subject, score);
-- 4. 查看表中所有索引
SHOW INDEX FROM student;
-- 5. 删除索引
DROP INDEX idx_student_name ON student;
```

索引使用原则：避免对频繁修改的字段建索引；模糊查询时%不要放在开头（否则索引失效）；联合索引遵循“最左前缀原则”。

# 第三阶段：数据库设计与优化

##  一、数据库设计三范式（避免数据冗余）

设计表结构时遵循的规范，核心是减少数据重复存储，保证数据一致性。

1. **第一范式（1NF）**：**字段不可再分（原子性）**。例：“联系方式”字段应拆分为“手机号”“邮箱”，而非存储“138xxxx1234;zhangsan@xxx.com”。

2. **第二范式（2NF）**：在1NF基础上，**非主键字段完全依赖于主键**（唯一性）（消除部分依赖）。例：成绩表中，“科目名称”不应依赖“student_id”，而应依赖“科目id”（需新增科目表）。

3. **第三范式（3NF）**：在2NF基础上，**所有非主键列之间不能存在”传递依赖“**（即非主键列不能依赖另一个非主键列）。例：学生表中，“班级名称”不应直接存储，应通过“班级id”关联班级表（班级表存储班级id、班级名称、班主任）。

注意：实际开发中可适当“反范式”（允许少量冗余），以提升查询效率（如电商订单表存储用户名，避免关联用户表查询）。

##  二、E-R图设计（可视化表关系）

E-R图（实体-关系图）用于描述实体（表）、属性（字段）、实体间关系（一对一、一对多、多对多），是数据库设计的核心工具。

###  1. 核心元素

- **实体**：矩形表示，对应数据库中的表（如学生、成绩、科目）。

- **属性**：椭圆形表示，对应表中的字段（如学生的id、姓名、年龄），主键属性加下划线。

- **关系**：菱形表示，对应表间的关联（如学生与成绩的“拥有”关系）。

###  2. 表间关系类型

- **一对多（最常见）**：一个实体对应多个另一个实体。例：一个学生可拥有多个成绩，一个成绩只属于一个学生（学生表id对应成绩表student_id）。

- **一对一**：一个实体对应一个另一个实体。例：一个学生对应一个身份证信息，一个身份证只属于一个学生（可在学生表加身份证id，或单独建身份证表关联学生id）。

- **多对多**：多个实体对应多个另一个实体。例：一个学生可选多门课程，一门课程可被多个学生选（需新增中间表，如学生课程表，存储student_id和course_id，双主键）。

工具推荐：PowerDesigner、Navicat（可视化工具自带E-R图功能）、DrawIO（在线免费）。

##  三、索引优化（提升查询效率）

索引是数据库的“目录”，能加快查询速度，但会降低插入/修改/删除速度（需维护索引），适用于查询频繁、数据量大的表。

###  1. 索引类型

- **主键索引**：默认自动创建，主键字段自带（唯一、非空），查询效率最高。

- **普通索引（INDEX）**：手动创建，用于频繁查询的字段（如学生表的name字段）。

- **唯一索引（UNIQUE）**：字段值唯一（可空），如手机号、邮箱字段（避免重复）。

- **联合索引**：对多个字段创建索引，适用于多字段联合查询（如score表的subject+student_id）。

###  2. 索引操作

```sql
-- 1. 创建普通索引
CREATE INDEX idx_student_name ON student(name);
-- 2. 创建唯一索引
CREATE UNIQUE INDEX idx_student_phone ON student(phone);
-- 3. 创建联合索引
CREATE INDEX idx_score_subject_studentid ON score(subject, student_id);
-- 4. 查看索引
SHOW INDEX FROM student;
-- 5. 删除索引
DROP INDEX idx_student_name ON student;
```

###  3. 索引使用原则

- 避免对频繁修改的字段建索引。

- 避免对数据量小的表建索引（反而增加开销）。

- 模糊查询时，%不能放在开头（如“%张”无法使用索引，“张%”可使用）。

- 联合索引遵循“最左前缀原则”（查询时需包含联合索引的第一个字段）。

##  四、事务管理（保证数据一致性）

事务（Transaction）是一组SQL操作的集合，要么全部执行成功，要么全部执行失败（如转账：扣款和到账必须同时成功或同时失败）。

###  1. 事务四大特性（ACID）

- **原子性（Atomicity）**：事务不可分割，要么全做，要么全不做。

- **一致性（Consistency）**：事务执行前后，数据总量保持一致（如转账前A有100，B有50；转账后A有80，B有70，总和不变）。

- **隔离性（Isolation）**：多个事务并发执行时，互不干扰。

- **持久性（Durability）**：事务执行成功后，数据永久保存到数据库，不可逆转。

###  2. 事务操作

```sql
-- 开启事务
START TRANSACTION;
-- 执行SQL操作（如转账：A扣20，B加20）
UPDATE user SET money = money - 20 WHERE name = 'A';
UPDATE user SET money = money + 20 WHERE name = 'B';
-- 提交事务（执行成功，永久生效）
COMMIT;
-- 回滚事务（执行失败，恢复到事务开启前状态）
-- ROLLBACK;
```

## 五、数据库拓展知识

###  2. 数据库权限管理

生产环境中，避免使用root账号操作，需创建专用账号并分配权限。

```sql
-- 1. 创建用户（用户名test，密码123456，仅本地访问）
CREATE USER 'test'@'localhost' IDENTIFIED BY '123456';
-- 2. 分配权限（给test账号school数据库的查询、插入权限）
GRANT SELECT, INSERT ON school.* TO 'test'@'localhost'; -- school.* 表示school库下所有表
-- 3. 分配单个表的权限（给test账号student表的修改权限）
GRANT UPDATE ON school.student TO 'test'@'localhost';
-- 4. 撤销权限（撤销test账号的插入权限）
REVOKE INSERT ON school.* FROM 'test'@'localhost';
-- 5. 查看用户权限
SHOW GRANTS FOR 'test'@'localhost';
-- 6. 删除用户
DROP USER 'test'@'localhost';
```
